### Category D: Product Strategy, Economics, & Monetization

#### Question 4.1: Monthly LLM Token Budget & Cost Ceiling
* **Context:** The intended architecture introduces foundation model API calls. Option 4 achieves an efficient \$0.01 – \$0.03 per analysis, but a public, unauthenticated tool without rate limits can be drained rapidly by web scrapers or bots.
* **What Could Not Be Determined:**
  - What is the owner's total monthly operating budget for LLM inference (e.g. \$20/month, \$100/month, \$500/month)?
  - Is the product intended to require user authentication (e.g. Supabase Auth / Clerk) or remain entirely anonymous?
* **Required to Resolve:**
  - **Owner Decision:** Monthly dollar budget ceiling and authentication policy (anonymous with IP rate-limiting vs. required user account).

#### Question 4.2: Frontend Framework Unification Decision
* **Context:** The frontend contains two competing UI paradigms:
  1. The 6-tab navigation shell in `web/src/App.jsx` styled with custom vanilla CSS (`index.css`).
  2. The deck builder dashboard in `web/src/LoreweaverDashboard.jsx` styled with Tailwind CSS.
* **What Could Not Be Determined:**
  - Which interface represents the intended future product experience?
* **Required to Resolve:**
  - **Owner Decision:** Authorize decommissioning the vanilla-CSS tab shell and consolidating the frontend into a single, unified Tailwind CSS application based on `LoreweaverDashboard.jsx`.
